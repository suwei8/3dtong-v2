# 滚动回测与特征消融：独立离线研究

本模块与每日预测、已封存的事前预测、实战排行榜以及原有200期预注册协议完全隔离。

## 研究设计

- 输入含 `Issue`、`KaiJiang` 的历史 CSV。号码以3字符字符串保存，支持 `015` 等前导0。
- 默认最后200期被排除在模型拟合、特征生成、测试和报告之外；在其余历史数据中最后120期做开发集滚动评估。
- 每20期重新拟合一次：仅使用该滚动块开始之前的历史标签；块内每期的75维特征仍严格使用该期之前已知的数据。
- 6种特征方案：完整特征、分别移除频率/遗漏间隔/位置频率/上期号码，以及仅使用频率。
- 额外与30期频率基线、SHA-256期号随机对照在完全相同的开发期号上比较。
- 训练模型是轻量的多输出 Ridge 排名研究模型，其输出不能当作已校准概率，也不等价于正式部署的XGBoost/LightGBM/CatBoost。
- 汇总同期开奖配对胜负、命中率和Wilson 95%区间；不计算可被反复挑选的显著性胜利结论。

## 执行步骤

在能够读取**已授权的私有历史数据**的机器上，从项目根目录执行：

```bash
python -m pip install -r requirements.txt
python -m pytest -q tests/
python -m src.research.rolling \
  --data /path/to/private/k3_full_history_test.csv \
  --holdout 200 --rounds 120 --refit-every 20 \
  --min-train 500 --out reports/experimental
```

命令运行完成后生成：

- `reports/experimental/rolling-ablation.md`：中文、可直接阅读的汇总报告
- `reports/experimental/rolling-ablation.json`：仅包含汇总值的机器可读报告

代码不会输出私有 CSV、实际开奖号码或逐期候选数字；内部逐期记录只用于测试，不会写入上述两份报告。只有真实执行并确认没有敏感信息后，才适合把汇总报告上传到GitHub。

## 科学性边界与下一阶段

这属于探索性特征筛选；多个特征消融共享相同期号，可能产生数据窥探偏差。**不因某组消融短期命中率更高就调整生产模型。**
最后200期虽然没有进入本次算法，但输入文件加载/验证仍可能读取这些行；如果此前已经人工检查过这些号码，那么它们不是真正意义上的未见盲测。
在冻结模型和研究方案后，才考虑单独启动一次最终隔离验证；最终验证数据不应参与新一轮调参。

真实开奖数据如果独立且均匀，任意3个不同候选数字命中至少一个的理论基准为65.7%。即使探索性指标短期高于该基准，也不能证明未来可预测，更不是投注收益证明。

## 可选：滚动评估当前三个生产机器学习模型

在上述命令后添加 `--include-current-models`，研究模块将用完全相同的开发期号、拟合边界和特征，额外训练并评估现有 XGBoost、LightGBM、CatBoost 实现，得到与 Ridge 及两个基准可直接配对比较的结果。这会明显增加运行时间；默认关闭，不会改变生产预测文件、正式排行榜或已封存数据。


## GitHub Actions 实际历史研究

新增 [独立滚动研究任务](../.github/workflows/rolling-research.yml)，仅在工作流配置变更或手动触发时执行，不会每天重复拟合，也不影响定时预测。

任务通过仓库已有的 PINBLE_DATA_TOKEN 只读签出私有 suwei8/pinble-data，在 runner 上完成120期开发滚动实验，并启用现有三个机器学习模型对照；最后200期仍不参与训练、评分或报告。

仅提交两个聚合文件：[中文实验报告](../reports/experimental/rolling-ablation.md) 和 [机器可读统计](../reports/experimental/rolling-ablation.json)。报告在首次实际运行成功后才生成。不得将合成数据CI测试解释为真实历史命中率。滚动回测结果不属于200期事前统计检验。
